# Relationship Ops

Seven small workflows that watch your messages, calendars and lists, and help you keep up with the things that matter to your partner. There's also a Sunday dashboard.

**Safety rules, built into the design:**
- **Dry-run is ON by default.** Workflows log what they *would* do and change nothing until you flip them live one at a time.
- **Nothing ever messages her.** There is no send path anywhere in the code. Nudges go to *you*, on your own machine.
- **Nothing ever completes a purchase.** Carts, orders and bookings stop at `AWAITING_APPROVAL`. Approving one only shows you the link, and you finish it yourself.

`tests/test_safety.py` checks all three by scanning the codebase.

## Quick start

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml        # then fill in real values (config.yaml is gitignored)
python3 cli.py status                     # what's enabled, what's live
python3 cli.py simulate-week              # full dry-run week on sample data -> PASS/FAIL
python3 -m unittest discover -s tests -t . # all tests
```

Put WhatsApp exports (open her chat → ⋮ → More → Export chat → *Without media*) into `imports/whatsapp/`. Put calendar `.ics` files, or Google "secret address in iCal format" URLs, in `config.yaml → calendars`.

## Layout

```
config.yaml / config.example.yaml   one config, read by every workflow
core/        config, context (dry-run enforcement), log, stores, approvals, extraction, schedule, simulator
adapters/    whatsapp (read), ics calendars (read), notify (you only), commerce (payloads + links only), notion (stub)
workflows/   one file per workflow (7)
dashboard/   sunday.py + reports/
data/        gift list, restaurants, friends CRM, approvals (gitignored); data/.dryrun/ = dry-run shadow copies
logs/        relops.jsonl — one format: ts, workflow, mode, kind, trigger evidence, action, status, data
scheduler/   crontab.txt (generated by `python3 cli.py crontab` from core/schedule.py)
samples/     fictional chat + calendars used by tests and the simulator
```

## The workflows

Each workflow has its own `workflows.<name>.enabled` flag (on/off) and its own `workflows.<name>.live` flag. A workflow is live only when the top-level `dry_run: false` **and** its own `live: true` are both set.

### 1. `reply_monitor`: every 5 min
- **Trigger:** her message has gone unanswered for 20+ min, or you sent (or drafted) a one-word reply like "k".
- **Data:** WhatsApp exports in `imports/whatsapp/`, drafts in `imports/drafts/*.txt` (or `cli.py check-draft "…"`).
- **Approval gate:** none needed, because it never acts outward. It nudges *you* locally and logs "k" replies as URGENT.

### 2. `gift_list`: hourly
- **Trigger:** she says "I want / I'd love / I need / I wish I had …". Separately, 14 days before her birthday it builds a cart.
- **Data:** WhatsApp exports → `data/gifts.json` (item, date, what she said, mention count).
- **Approval gate:** the Amazon cart (top 3 items, links only) halts at `AWAITING_APPROVAL`.

### 3. `date_night`: Mondays 09:00
- **Trigger:** Monday. It looks for an evening (18:30–22:00) this week when both calendars are free, then picks the top unvisited place.
- **Data:** both calendars plus `data/restaurants.json` (seeded from config, with places she mentions added automatically).
- **Approval gate:** the booking (date, time, party size, OpenTable/Resy link) halts at `AWAITING_APPROVAL`.

### 4. `friends_crm`: hourly
- **Trigger:** she mentions a friend; also, any calendar event within the next 48h that involves a logged friend.
- **Data:** WhatsApp exports → `data/friends.json`; both calendars. Briefings are written to `data/briefings/`.
- **Approval gate:** none needed, because it only writes notes and briefings for you.

### 5. `long_shift`: 07:00 and 13:00
- **Trigger:** her calendar shows a non-all-day event of 12+ hours (keyword filter optional).
- **Data:** her calendar; `workflows.long_shift.order / service / address_label`.
- **Approval gate:** the 18:00 food order halts at `AWAITING_APPROVAL`. No payment code exists.

### 6. `random_flowers`: daily 10:00
- **Trigger:** one secret random day in each 6–8 week window (never within 4 days of her birthday). The order is prepared 2 days ahead.
- **Data:** `workflows.random_flowers` budget cap, florist and avoid list; state in `data/flowers_state.json`.
- **Approval gate:** the flower order halts at `AWAITING_APPROVAL`.

### 7. `referee`: invoke-only, never scheduled
- **Trigger:** you run `python3 cli.py referee thread.txt [--last N | --since … --until …]` on a heated thread.
- **Data:** only the export file you point it at. Analysis runs locally, so the thread never leaves your machine.
- **Approval gate:** the output is a private draft for you (`data/referee/`): what each of you said, an honest read on your missteps, and an apology to deliver **in person**. It never sends anything.

### Sunday dashboard: Sundays 19:00
`python3 cli.py dashboard` reads the week's logs and reports four headline metrics, each compared with last week:
- average reply time
- date nights booked / held
- gifts saved / ordered
- "k"-style replies sent (target 0)

Any metric that got worse is called out in plain language with a specific fix, e.g. *"Reply time slipped to 22 min (from 4) — 3 thread(s) went past 20 min on Tue/Thu."* The report also covers per-workflow activity, pending approvals and upcoming milestones. It prints to the terminal and is saved to `dashboard/reports/YYYY-MM-DD.md`.

## Approvals

```bash
python3 cli.py approvals list [--dry-run]     # dry-run proposals live in a separate shadow queue
python3 cli.py approvals show <id>
python3 cli.py approvals approve <id>         # records your yes + prints the link(s); YOU finish it
python3 cli.py approvals reject <id>
python3 cli.py approvals done <id>            # gift ordered / date night held (marks restaurant visited)
```

## Going live, one workflow at a time

1. Run `python3 cli.py simulate-week` and confirm it reports **PASS**.
2. In `config.yaml`, set `dry_run: false`. Every workflow is still dry until its own flag is flipped.
3. Set `workflows.reply_monitor.live: true`, run it for a week, then move to the next workflow.
4. Install the schedule with `python3 cli.py crontab | crontab -`, with `TZ`/`CRON_TZ` matching `timezone`.

## Integrations and the access you actually have

| Integration | Status | What's missing to go further |
|---|---|---|
| WhatsApp | **Manual import** of "Export chat" `.txt` files (Android and iOS formats) | WhatsApp has no personal-account read API. Real-time nudges are only as fresh as your last export. |
| Google Calendar (yours and hers) | **Read-only `.ics`** via file or the calendar's *secret iCal address* | She has to share her calendar with you (or give you its secret address). No OAuth app is wired. |
| Data stores | **Local JSON** in `data/` (your choice) | `adapters/notion.py` is a stub: it needs a Notion integration token plus database IDs. |
| Amazon / food delivery / florist / OpenTable | **Links and payloads only** | By design there are no purchase or booking APIs. You finish each order yourself after approving. |
